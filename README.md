# VCMX2STP — конвертер KUKA.Sim (.vcmx) в STEP (.stp)

Программа для Windows 10/11, которая переводит компоновки и компоненты **KUKA.Sim Pro / Visual Components**
(`*.vcmx`) в файл **STEP AP214** (`*.stp`), пригодный для импорта в Creo, SolidWorks, КОМПАС-3D, NX, Inventor и т. д.

## Что делает

* **Структура сборок.** Layout → компоненты → звенья кинематики (J1…J6, rSimLink) → детали.
  Одинаковые компоненты и детали записываются один раз и вставляются как экземпляры (меньше размер файла).
* **Без треугольников.** В STEP пишется только точная геометрия B-rep (`ADVANCED_FACE`, `MANIFOLD_SOLID_BREP`):
  * примитивы KUKA.Sim (Block, Cylinder, Cone, Sphere, Wedge, Extrude, Revolve) — аналитическими поверхностями;
  * встроенные сетки (формат 3DS внутри `.vcmx`) — компланарные треугольники сливаются в плоские
    многоугольные грани с отверстиями, замкнутые оболочки становятся твёрдыми телами.
  Тесселированные сущности (`TRIANGULATED_FACE`, `TESSELLATED_*`) не записываются.
* **Минимальный размер.** Повторное использование прототипов, отказ от лишних кривых на поверхностях
  (`write.surfacecurve.mode = 0`), сжатие текста STEP (без изменения данных).
* **Все объекты.** Переносятся все видимые элементы: Geo, примитивы, Transform, Switch, Linear/Angular Clone, Mirror,
  выражения параметров (`Length`, `Radius`, свойства компонента), положения осей, цвета материалов.
  Опционально — скрытые элементы и рабочие зоны роботов.
* **Предупреждение о недостающих моделях.** Если элемент ссылается на геометрию, которой нет в `.vcmx`
  (layout сохранён без «Include Components», ссылка `vcid:…` на eCatalog, внешний CAD-файл), программа
  показывает окно **«В файле не хватает встроенных моделей»** со списком объектов. В CLI — сообщение и,
  с ключом `--strict`, код возврата 2. Можно указать папки с исходными компонентами — геометрия будет
  найдена по VCID.
* **Обновление.** Программа проверяет GitHub Releases и по запросу скачивает и тихо устанавливает новую версию.

## Использование

### Окно
`Пуск → Конвертер VCMX в STEP`, либо правой кнопкой по файлу `.vcmx` → **«Конвертировать в STEP (VCMX2STP)»**.
Добавьте файлы, выберите папку результата и нажмите «Конвертировать».

### Командная строка
```bat
"%LOCALAPPDATA%\Programs\VCMX2STP\vcmx2stp-cli.exe" cell.vcmx -o cell.stp
vcmx2stp-cli.exe C:\Layouts\*.vcmx -o D:\STEP --strict
vcmx2stp-cli.exe robot.vcmx -s "C:\Users\Public\Documents\Visual Components\4.9\Models"
```
Ключи: `-o` — файл или папка, `-s` — папка поиска невстроенных компонентов (можно несколько),
`--hidden` — скрытые элементы, `--envelopes` — рабочие зоны, `--no-colors`, `--angle-tol 0.5` — допуск слияния
граней (градусы), `--strict` — код 2 при недостающих моделях.

### Запуск из исходников
```bat
py -3.12 -m pip install -r requirements.txt
set PYTHONPATH=src
py -3.12 -m vcmx2stp            :: окно
py -3.12 -m vcmx2stp --cli file.vcmx -o file.stp
```

## Сборка через GitHub Actions

1. Создайте репозиторий на GitHub (например `vcmx2stp`) и загрузите в него **всё содержимое архива**
   (папка `.github` обязательна). Через веб-интерфейс: *Add file → Upload files*; через git:
   ```bash
   git init && git add . && git commit -m "VCMX2STP 1.0.0"
   git branch -M main
   git remote add origin https://github.com/<логин>/vcmx2stp.git
   git push -u origin main
   ```
   Если `git push` отклоняется с сообщением про `workflow` — токену нужен scope **workflow**
   (Settings → Developer settings → Personal access tokens) или загрузите файлы через веб-интерфейс.
2. Вкладка **Actions** → workflow **Build Windows installer** запустится сам (или *Run workflow*).
   Через ~10–15 минут в разделе *Artifacts* появится `VCMX2STP-<версия>` с установщиком и portable-архивом.
3. **Выпуск версии с обновлением.** Создайте тег:
   ```bash
   git tag v1.0.0 && git push origin v1.0.0
   ```
   Workflow соберёт `VCMX2STP-Setup-1.0.0.exe` и опубликует **Release**. Для следующей версии — `v1.0.1` и т. д.
   Установленные программы увидят новый Release (меню «Справка → Проверить обновления» или автоматически
   при запуске) и предложат обновиться.

Проверки в workflow: модульные тесты (`pytest`), сборка PyInstaller, тестовая конвертация синтетического
`.vcmx` собранным `vcmx2stp-cli.exe` (контроль отсутствия треугольников и наличия сборок), сборка Inno Setup.

### Обновления
* Адрес репозитория для обновлений подставляется при сборке (`GITHUB_REPOSITORY`) и меняется в меню
  «Настройки → Репозиторий обновлений GitHub…».
* Обновления читаются через публичный API `releases/latest`; для приватного репозитория задайте переменную
  окружения `VCMX2STP_GITHUB_TOKEN` (токен только на чтение).
* Установщик имеет постоянный `AppId`, поэтому ставится поверх старой версии, настройки сохраняются.
  По умолчанию установка идёт без прав администратора в `%LOCALAPPDATA%\Programs\VCMX2STP`.

## Структура проекта
```
.github/workflows/build.yml   сборка, тесты, установщик, Release
src/vcmx2stp/                 исходный код
  archive.py                  чтение .vcmx (ZIP), поиск встроенной/внешней геометрии по VCID
  rsc_parser.py, expr.py      разбор layout.rsc/component.rsc и выражений параметров
  model.py                    дерево сцены: компоненты, звенья, features
  mesh3ds.py, geometry.py     чтение 3DS / STEP / IGES / STL
  brep.py                     примитивы, сетка → плоские грани B-rep, трансформации
  step_writer.py              запись STEP AP214 со сборками (OpenCascade XCAF)
  converter.py, cli.py, gui.py, updater.py, config.py
packaging/                    PyInstaller (VCMX2STP.exe + vcmx2stp-cli.exe)
installer/vcmx2stp.iss        Inno Setup
tests/                        тесты и генератор тестового .vcmx
tools/set_version.py          версия из тега git
```

## Ограничения
* KUKA.Sim хранит импортированную CAD-геометрию уже **тесселированной** (сетка треугольников), исходные
  NURBS-поверхности в `.vcmx` отсутствуют. Плоские участки восстанавливаются точно; криволинейные
  (цилиндры, скругления деталей из CAD) передаются плоскими многоугольными гранями — это B-rep, но
  для роботов с большим количеством скруглений размер файла может составлять десятки мегабайт.
* Формат `.rsc` закрытый и описан по документации и реальным файлам; редкие features
  (скрипты Python, генерирующие геометрию на лету, облака точек, текст) не переносятся — о них выводится
  сообщение в журнале.
* Положения звеньев берутся в исходной (сохранённой) позе.
